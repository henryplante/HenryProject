# ClearPath Review — web

Next.js 15 (App Router), TypeScript (strict), Tailwind CSS v4, shadcn/ui (radix, `vega` preset, neutral theme), TanStack Query, `react-pdf`, MSW.

## Run

```bash
cp .env.example .env.local   # optional
npm install
npm run dev                  # http://localhost:3000, expects the API on API_URL
```

| Script | What it does |
| --- | --- |
| `npm run dev` | Dev server (Turbopack) |
| `npm run build` / `npm start` | Production build / server |
| `npm run lint` | ESLint |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run generate:api` | `openapi-typescript ../contracts/openapi.yaml -o lib/api/schema.d.ts` |
| `npm run e2e` | Real-API Playwright suite (`e2e/*.spec.ts`; starts `npm run dev` on `PORT`, default 3100, unless `E2E_BASE_URL` targets a running stack). `scripts/e2e-real.sh` runs the whole flow (see `e2e/README.md`). First run: `npx playwright install chromium` |

## Environment

| Variable | Default | Notes |
| --- | --- | --- |
| `API_URL` | `http://localhost:8080` | Spring API origin that `/api/*` is proxied to. Read in `next.config.ts` **at build/dev-start time**: for `next build` / `next start` / Vercel it must be set when building, not only when starting. |
| `NEXT_PUBLIC_API_MOCKS` | unset | `1` starts the MSW browser worker (`mocks/browser.ts`, handlers in `mocks/handlers.ts`) before the app renders. Also build-time (`NEXT_PUBLIC_*`). |

## API proxy

`next.config.ts` rewrites `/api/:path*` to `${API_URL}/api/:path*`, so the browser only talks to the Next origin (no CORS; the session cookie stays on the web origin).

Request bodies that pass through a rewrite are buffered by Next up to `experimental.middlewareClientMaxBodySize` (10 MB by default). This is the Next 15.5 name of the option that later versions call `proxyClientMaxBodySize`. It is set to `50mb` so multipart PDF uploads work; larger bodies are truncated and the proxied request fails. If Next is upgraded to a version that renames the option, rename it in `next.config.ts`. The API must enforce its own upload limit (same or lower).

## Layout

- `app/(app)/` — routes inside the app shell: `/`, `/library`, `/setup`, `/materials/[id]`
- `app/(auth)/login/` — `/login`, no shell
- `components/providers.tsx` — React Query, tooltip provider, toaster, optional MSW start
- `components/shell/` — `AppShell`, `NavLinks`, `HeaderActions` (right-side header slot), `LoginForm`
- `components/tasks/TaskPane.tsx`, `components/material/MaterialView.tsx`, `components/library/LibraryView.tsx`, `components/setup/SetupView.tsx` — stubs that feature tickets replace wholesale; pages only import these, so page files do not change
- `components/ui/` — shadcn primitives; add more with `npx shadcn@latest add <name>`
- `mocks/` — MSW (`handlers.ts` + stateful in-memory store; see `lib/README.md`)
- `lib/pdf-worker.ts` — configures the `react-pdf` worker

Home is `/?m=<materialId>&v=<versionId>`; the page passes both to `TaskPane` / `MaterialView`.

## Notes

- **react-pdf worker:** `lib/pdf-worker.ts` sets `pdfjs.GlobalWorkerOptions.workerSrc = new URL("pdfjs-dist/build/pdf.worker.min.mjs", import.meta.url)`, which Next (webpack and Turbopack) bundles as an asset, so no copy step into `public/` is needed. `pdfjs-dist` is pinned to the exact version `react-pdf` depends on (6.3.289); keep them in sync when upgrading. Import `@/lib/pdf-worker` (not `react-pdf` directly) from the PDF component and load that component with `next/dynamic` and `ssr: false`, since pdf.js needs browser APIs.
- **MSW 3:** the option for passthrough is `onUnhandledFrame` (not `onUnhandledRequest`). `msw/browser` has no `node` export condition, so `next.config.ts` aliases it to `mocks/empty.ts` for server-side compilation. `public/mockServiceWorker.js` is generated by `npx msw init public/ --save` and re-generated on MSW upgrades.
- **shadcn:** `lib/utils.ts` uses `clsx` + `tailwind-merge`. Dark mode tokens exist but there is no theme switcher; the app is light only.
- **Shared UI pieces:** `components/status-badge.tsx` + `lib/status.ts` own status/expiry wording and colors (Draft, In review, Approved until, Expired, Obsolete, "Expires in N days" within 30 days) for the banner, library and task rows. `components/empty-state.tsx` and `components/error-state.tsx` are the only empty/error patterns; use them instead of ad-hoc text.
- **Return path after login:** a 401 sends the browser to `/login?next=<path>` (`lib/auth-redirect.ts`); the login form honors `next` (same-origin paths only). An explicit sign-out does not set `next`.
- **Mock controls in tests:** with mocks on, `window.__clearpathMocks` exposes `{ worker, db, http, HttpResponse }` so Playwright specs can add handlers (`worker.use`) or edit the in-memory db to reach empty and error states.
- **Dialogs:** `components/ui/dialog.tsx` returns focus to the element that opened the dialog even when it is opened programmatically (no `DialogTrigger`).
